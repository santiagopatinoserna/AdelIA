## 1. Goal

Eliminate the #1 adoption risk identified in spec rev 2 §14: **"Adopción cero porque ingestion sigue siendo fricción incluso con web | Crítica"**. Reframe AdelIA from "personal vault with manual web upload" to a **"Liberate Your Data" hub**: the user exercises their legal right to data portability (GDPR, HIPAA), exports from whatever system holds their data, and forwards it to AdelIA via the path of least friction.

M4 ships:
1. **Telegram bot** — user forwards file/photo/audio to bot → ingested automatically.
2. **Email forwarding** — user's unique `<id>@in.adelia.app` address → ingested automatically.
3. **Import wizard UI** — step-by-step guides for top 5 platforms with parsers for structured exports.
4. **GDPR request templates** — pre-filled email templates for platforms that require formal data subject access requests.

## 2. Non-goals (M4 explicit cuts)

- ❌ Real-time API integration with Apple Health (requires iOS app + HealthKit entitlement — v0.2 if PWA → native)
- ❌ Mon Espace Santé FHIR API (requires INS auth + government approval — v0.3)
- ❌ MyChart SMART on FHIR live sync (CCD export covers 90% — full SMART in v0.3)
- ❌ WhatsApp Business API ingestion (requires business verification + €80/mo — v0.2)
- ❌ Fitbit/Garmin/Withings parsers — v0.1.1 (low-value vs medical history)
- ❌ Apple Health `electrocardiograms/` folder — v0.1.1 (specialized parser, raw_text already extractable via OCR)
- ❌ Postal self-host email — v0.2 (Postmark Inbound suffices v0.1)

## 4. Architecture

### Boundaries (M4 NEW units)

```
M4 NEW units:
  - telegram_bot.py            → handler + webhook + polling mode
  - telegram_link_repo         → /start <token> → link AdelIA user ↔ Telegram chat_id
  - email_inbound.py           → Postmark Inbound webhook handler
  - apple_health_parser.py     → export.xml → list[EntityInput-like records]
  - ccd_parser.py              → CCD XML → entities + raw_text (reusable for MyChart/Cerner/Athena)
  - ingestion_router.py        → endpoints /ingestion/telegram/webhook + /ingestion/email/webhook
  - import_wizards/            → 5 markdown platform guides served via Next.js
  - gdpr_templates/            → 3 markdown templates (ES + FR + US)

M4 REUSES (no rebuild):
  - process_document M1 pipeline (Telegram + email files just POST internally to /documents)
  - Document + Entity + Chunk ORM models (M2)
  - S3 storage (M1)
  - Stale hook (M5) — every ingestion path automatically triggers stale flag
  - Auth (Auth.js + JWT bridge)
```

### Data flow Telegram

```
1. User opens AdelIA web → /dashboard/ingestion/telegram
2. Page shows "Open @adelia_vault_bot in Telegram + send /start <signed_token>"
3. User opens bot, sends /start. Bot validates token, links chat_id to user_id in telegram_links table.
4. User forwards a photo/PDF/audio/voice msg to bot.
5. Bot webhook receives update → bot.handlers.on_file_received(update):
   a. Download file via Bot API
   b. Determine MIME type
   c. POST internal /documents endpoint with file body + user_id (looked up from chat_id)
   d. Send "✅ Recibido, procesando..." reply
6. Existing process_document pipeline ingests as if uploaded via web.
7. When stale hook fires → existing briefings marked is_stale.
```

### Data flow Email

```
1. User opens /dashboard/ingestion/email
2. Page shows their unique address: <user_id_short>@in.adelia.app
3. User sets up email forwarding rules in Gmail/Outlook (one-time, guide provided)
4. User receives a hospital email with PDF attachment → forwards to <id>@in.adelia.app
5. Postmark Inbound parses MIME → POSTs JSON webhook to /ingestion/email/webhook
6. Handler validates Postmark signature, extracts attachments, POSTs each to internal /documents
7. User receives confirmation email "AdelIA ingested 2 attachments from <subject>"
```

### Data flow Apple Health import wizard

```
1. User opens /dashboard/ingestion/import → selects "Apple Health"
2. Wizard step 1: instructions screenshot (Settings > Health > Export All Health Data)
3. Step 2: drag-drop the resulting export.zip
4. Frontend uploads to backend /ingestion/apple-health/import endpoint
5. Backend unzips → reads export.xml → apple_health_parser yields HealthRecord items
6. For each HealthRecord:
   - Create an Entity directly (entity_type=observation, value={value, unit, type}, event_date, provenance=patient_stated)
   - Create a Document row marking the import batch (so user can audit)
7. Bulk insert with session.flush every 500 records (memory bound)
8. Stale hook fires once at end.
9. User redirected to /dashboard with success: "Imported 12,847 observations from Apple Health"
```

## 5. Data model additions

```sql
-- 5.1 Migration `0004_ingestion_surfaces`
CREATE TABLE telegram_links (
  user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  chat_id BIGINT NOT NULL UNIQUE,
  username TEXT,
  linked_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE email_aliases (
  user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  alias TEXT NOT NULL UNIQUE,        -- e.g. "abc123@in.adelia.app"
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_email_aliases_alias ON email_aliases(alias);

CREATE TABLE ingestion_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  source TEXT NOT NULL CHECK (source IN ('web', 'telegram', 'email', 'apple_health', 'ccd_import', 'gdpr_response')),
  document_count INT NOT NULL DEFAULT 0,
  entity_count INT NOT NULL DEFAULT 0,
  error_message TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_ingestion_events_user ON ingestion_events(user_id, created_at DESC);
```

Existing `documents.source` enum gets extended: `'web' | 'manual'` → `'web' | 'manual' | 'telegram' | 'email' | 'apple_health' | 'ccd_import' | 'gdpr_response'`.

## 7. Endpoints

```
POST   /ingestion/telegram/webhook         → bot updates from Telegram (validates secret)
GET    /ingestion/telegram/link            → returns signed token + bot URL for /start
DELETE /ingestion/telegram/link            → unlink

POST   /ingestion/email/webhook            → Postmark Inbound JSON (validates signature)
GET    /ingestion/email/alias              → returns user's <id>@in.adelia.app + setup guide URLs

POST   /ingestion/apple-health/import      → multipart upload .zip → bulk entity insert
GET    /ingestion/events                   → list user's ingestion_events (audit log)

GET    /ingestion/guides                   → list available platform guides (slug + title)
GET    /ingestion/guides/{slug}            → markdown body (served via Next.js)
GET    /ingestion/gdpr-templates           → list available country templates
GET    /ingestion/gdpr-templates/{country} → pre-filled markdown template
```

Cross-user isolation enforced at every endpoint via `Depends(get_current_user_id)` (except `/webhook` paths which use external signature validation).

## 8. Webhook security

### Telegram
- Set secret token via `setWebhook(secret_token=...)` then validate `X-Telegram-Bot-Api-Secret-Token` header on every POST.
- Bonus: rate-limit per chat_id to 10 req/min.

### Postmark Inbound
- Postmark sends JSON with HMAC signature in `X-Postmark-Signature` header.
- Validate against PMI server token (stored in `POSTMARK_INBOUND_TOKEN` env var).
- Reject mismatched signature with 401.

## 9. Apple Health export.xml parser

Apple Health `export.xml` schema (simplified):

```xml
<HealthData>
  <ExportDate value="2026-05-18 10:30:00 +0200"/>
  <Me HKCharacteristicTypeIdentifierBiologicalSex="HKBiologicalSexFemale"
      HKCharacteristicTypeIdentifierDateOfBirth="1985-03-15"/>
  <Record type="HKQuantityTypeIdentifierBodyMass"
          sourceName="Apple Watch"
          startDate="2025-12-10 08:30:00 +0200"
          endDate="2025-12-10 08:30:00 +0200"
          value="58.4"
          unit="kg"/>
  <Record type="HKQuantityTypeIdentifierBloodGlucose"
          sourceName="Dexcom G7"
          startDate="2026-05-18 09:15:00 +0200"
          endDate="2026-05-18 09:15:00 +0200"
          value="142"
          unit="mg/dL"/>
  ...
</HealthData>
```

The parser:
- Streams XML (don't load 500MB into memory)
- Maps `HKQuantityTypeIdentifier*` to AdelIA `Entity.name` (lookup table)
- Sets `entity_type='observation'`, `value={value, unit, type, source}`, `event_date=startDate.date()`, `provenance='patient_stated'`, `raw_quote=f"{type}={value} {unit} from {sourceName} on {startDate}"`
- Bulk inserts every 500 records to bound memory
- Returns total count for ingestion_events

## 10. CCD XML parser (HL7 C-CDA)

C-CDA documents are XML in HL7 standard. Parser extracts:
- Patient demographics → PatientHeader update
- Allergies → entity_type='allergy', name from CDA Allergy section
- Medications → entity_type='medication', name + dose + frequency
- Problems → entity_type='condition'
- Procedures → entity_type='procedure'
- Vital signs → entity_type='observation'
- Immunizations → entity_type='immunization'
- Lab results → entity_type='observation'

Reuses provenance='extracted_from_clinician_doc' since CCD originates from a healthcare provider.

## 15. Risks specific to M4

| Risk | Severity | Mitigation |
|------|----------|------------|
| Telegram webhook signature bypass | Critical | `X-Telegram-Bot-Api-Secret-Token` validated on every POST; reject with 401 |
| Postmark signature bypass | Critical | HMAC verified; constant-time comparison; reject with 401 |
| Apple Health XML > 1GB → OOM | High | Stream parsing via `lxml.etree.iterparse` + bulk insert every 500 records |
| Malicious file via Telegram (zip bomb, executable) | High | Validate MIME against M1 allowlist (PDF/PNG/JPEG/MPEG/WAV); reject others with friendly bot reply |
| User links wrong Telegram account (impersonation) | High | /start token signed (JTI + expiry 1 hour), single-use; chat_id must be unique per AdelIA user |
| Postmark email forwarding attaches PHI to wrong user | High | Alias `<random_8_chars>@in.adelia.app` is opaque secret; signed unique per user; rotate-able via UI |
| GDPR template legal liability (wrong country law) | Medium | "Template is informational, not legal advice" disclaimer in every template |
| Email loops (forwarded to self) | Low | Detect `X-AdelIA-Origin` header on outbound, reject inbound matching |
